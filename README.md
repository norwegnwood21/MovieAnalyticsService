# Веб-сервис «Киноразбор»

## 1. Назначение проекта

«Киноразбор» — учебное веб-приложение для аналитики пользовательского списка фильмов. Пользователь вводит несколько названий фильмов, система обращается к официальному REST API TMDB, сопоставляет названия с найденными фильмами, получает подробные данные и строит аналитическую сводку.

Приложение реализует требования ТЗ:

- регистрация и аутентификация пользователей;
- создание нового аналитического запроса;
- ввод нескольких названий фильмов в одном запросе;
- поиск и сопоставление фильмов через TMDB API;
- получение детальной информации о фильмах;
- сохранение введённых данных, ответов TMDB, логов внешнего API и результата анализа в PostgreSQL;
- отображение статуса отчёта: `RUNNING`, `COMPLETED`, `ERROR`;
- просмотр истории отчётов;
- отображение краткой информации по каждому фильму;
- отображение визуализаций: распределение по жанрам, годам выпуска и актёрам;
- повторный анализ ранее сохранённого списка без повторного обращения к TMDB;
- удаление отчёта из локальной базы данных.

## 3. Использованные паттерны проектирования

В проекте используются паттерны разных категорий.

### Adapter / Адаптер

Используется для интеграции с TMDB. Приложение работает с интерфейсом `MovieDataProvider`, а класс `TmdbMovieDataAdapter` переводит внутренние вызовы приложения в вызовы низкоуровневого клиента `TmdbHttpClient`.

### Facade / Фасад

Класс `AnalysisFacade` является единой точкой запуска анализа. Он скрывает от контроллера работу с TMDB, БД, состояниями отчёта, Builder и аналитическими стратегиями.

### Builder / Строитель

Используется для формирования сложного объекта результата анализа. Реализованы `AnalysisResultBuilder`, `DefaultAnalysisResultBuilder`, `AnalysisResult` и обязательный `AnalysisDirector`, который задаёт порядок шагов построения.

### Strategy / Стратегия

Используется для независимых алгоритмов аналитики. Реализованы `GenreAnalysisStrategy`, `YearAnalysisStrategy`, `CastAnalysisStrategy` и общий интерфейс `AnalysisStrategy`.

### State / Состояние

Используется для обработки статуса отчёта. Реализованы `ReportState`, `RunningState`, `CompletedState`, `ErrorState` и `ReportStatusContext`.

## 4. Настройка PostgreSQL через pgAdmin 4

1. Открыть pgAdmin 4.
2. Подключиться к локальному серверу PostgreSQL.
3. Создать новую базу данных:

```text
movie_analytics_db
```

4. Проверить настройки подключения в файле:

```text
src/main/resources/application.properties
```

Пример настроек:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/movie_analytics_db
spring.datasource.username=postgres
spring.datasource.password=postgres
spring.jpa.hibernate.ddl-auto=update
```

Если пароль от PostgreSQL другой, нужно заменить значение `spring.datasource.password`.

Таблицы вручную создавать не нужно. Hibernate создаёт и обновляет таблицы автоматически при запуске приложения.

## 5. Настройка TMDB

В файле:

```text
src/main/java/org/example/movieanalytics/service/tmdb/TmdbHttpClient.java
```

найти строку:

```java
private final String token = "";
```

и вставить туда `API Read Access Token` из TMDB:

```java
private final String token = "eyJhbGciOiJIUzI1NiJ9...";
```

Важно: для учебной локальной проверки токен можно вставить прямо в код, но перед публикацией проекта в GitHub его нужно удалить.

## 7. Основной пользовательский сценарий

1. Пользователь регистрируется или входит в систему.
2. Вводит список фильмов, каждый фильм с новой строки.
3. Нажимает «Запустить анализ».
4. Система создаёт отчёт со статусом `RUNNING`.
5. Для каждого фильма система выполняет поиск в TMDB.
6. Система сохраняет найденные варианты и выбирает первый вариант как базовое сопоставление.
7. Система получает детальную информацию о выбранном фильме.
8. Полученные данные сохраняются в PostgreSQL.
9. Приложение строит аналитику внутри приложения, не перекладывая её на TMDB.
10. Отчёт получает статус `COMPLETED` или `ERROR`.
11. Пользователь видит:
    - сопоставление фильмов;
    - краткую информацию по каждому фильму;
    - распределение по жанрам;
    - распределение по годам;
    - самых часто встречающихся актёров;
    - историю отчётов.

## 8. Дополнительная функция

Реализована возможность повторного анализа без обращения к внешнему API.

Кнопка:

```text
Повторить без TMDB
```

создаёт новый отчёт на основе уже сохранённых в БД данных `tmdbDetailsJson`. Новых HTTP-запросов к TMDB в этом сценарии не выполняется.

Это повышает устойчивость приложения: даже если внешний API временно недоступен, пользователь может повторно построить аналитику по уже сохранённым данным.

## 9. Удаление отчёта

В истории отчётов есть кнопка:

```text
Удалить
```

Она вызывает endpoint:

```http
DELETE /api/reports/{id}
```

При удалении из локальной БД удаляются:

- сам аналитический отчёт;
- введённые фильмы отчёта;
- сохранённые данные TMDB, связанные с этими фильмами;
- логи обращений к TMDB, связанные с отчётом.

## 10. Обработка ошибок

Приложение обрабатывает:

- отсутствие или неправильный TMDB token;
- ошибку авторизации TMDB `401`;
- отсутствие ресурса `404`;
- неверные параметры запроса `422`;
- превышение лимитов `429`;
- ошибки TMDB `5xx`;
- сетевые сбои;
- ситуацию, когда фильм не найден;
- попытку открыть или удалить чужой отчёт;
- пустой список фильмов.

Если TMDB недоступен, введённые пользователем данные не теряются: отчёт сохраняется со статусом `ERROR`.

## 11. Тестирование

В проект добавлены unit-тесты и интеграционные тесты.

### Unit-тесты

1. `GenreAnalysisStrategyTest` — проверяет подсчёт жанров.
2. `YearAnalysisStrategyTest` — проверяет извлечение года из даты выхода.
3. `AnalysisDirectorTest` — проверяет построение полного результата через Builder + Director.

### Интеграционные тесты

1. `AppUserRepositoryIntegrationTest` — проверяет сохранение и поиск пользователя через JPA repository.
2. `AnalysisReportRepositoryIntegrationTest` — проверяет сохранение отчёта с фильмами и поиск отчётов пользователя.

Для запуска тестов выполнить:

```bash
mvn test
```

Для запуска одного тестового класса:

```bash
mvn -Dtest=GenreAnalysisStrategyTest test
```

Для запуска только интеграционных тестов репозиториев:

```bash
mvn -Dtest=*RepositoryIntegrationTest test
```

## 12. Тест-кейсы для ручной проверки

### Тест-кейс 1. Регистрация

Шаги:

1. Открыть `http://localhost:8080`.
2. Ввести username, email и password.
3. Нажать «Зарегистрироваться».

Ожидаемый результат:

- появляется сообщение «Регистрация выполнена»;
- открывается форма создания аналитического запроса;
- пользователь сохраняется в таблице `app_users`.

### Тест-кейс 2. Вход

Шаги:

1. Ввести существующие username и password.
2. Нажать «Войти».

Ожидаемый результат:

- появляется сообщение «Вход выполнен»;
- отображается имя пользователя;
- становится доступна история отчётов.

### Тест-кейс 3. Создание отчёта

Шаги:

1. Ввести фильмы, например:

```text
Green mile
Forrest Gump
Titanic
```

2. Нажать «Запустить анализ».

Ожидаемый результат:

- создаётся новый отчёт;
- фильмы сопоставляются с TMDB;
- выводится краткая информация по каждому фильму;
- отображаются распределения по жанрам, годам и актёрам;
- отчёт появляется в истории.

### Тест-кейс 4. Повторный анализ без TMDB

Шаги:

1. В истории найти завершённый отчёт.
2. Нажать «Повторить без TMDB».

Ожидаемый результат:

- создаётся новый отчёт;
- данные берутся из локальной БД;
- новые обращения к TMDB не выполняются;
- результат анализа отображается на странице.

### Тест-кейс 5. Удаление отчёта

Шаги:

1. В истории отчётов нажать «Удалить».
2. Подтвердить удаление.

Ожидаемый результат:

- отчёт исчезает из истории;
- данные отчёта удаляются из локальной БД.

## 15. Замечание по языку данных TMDB

Запросы к TMDB выполняются с параметром `language=ru-RU`, поэтому большинство названий, жанров и описаний возвращаются на русском языке. Однако часть имён актёров или других данных может остаться на английском языке, если в TMDB нет русской локализации для конкретного человека или поля. Это нормальное поведение внешнего API.
